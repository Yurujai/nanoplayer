Analytics and xAPI

Two plugins send viewing data out of the player: analytics for your statistics, xAPI for your learning platform. Both are off until configured, both read the player's event bus, and neither stops playback when its destination fails.

How analytics sends

import '@nanoplayer/plugin-analytics';

create('#player', {
  manifest,
  plugins: {
    analytics: {
      endpoint: 'https://stats.example.org/collect',
      // or: send: (events) => { … },
      context: { course: 'PHY-101' },
    },
  },
});
  • In batches, not one request per event: every 10 seconds (flushEvery), as soon as 20 events are waiting, when the tab is hidden, and when the page goes away.
  • To an endpoint, each batch is a POST whose body is a JSON array of events, sent with keepalive and Content-Type: application/json.
  • As the page goes away, the last batch goes by navigator.sendBeacon, which survives closing the tab but carries no headers and is sent as text/plain. So the server should parse the body as JSON whatever its type, and authenticate by a token in the URL or a cookie, not by a header.
  • With send, your function gets each batch as an array and forwards it anywhere: an analytics library, your own API, a queue.
  • Failures are dropped, without retries: analytics must never slow down or break a lecture.
  • Cross-origin endpoints must allow the page's origin (CORS) for the fetch batches.

The event

FieldWhat it is
typeThe bus event, play or seek:end, or a derived one: milestone, session:end.
timeWhen it happened, ISO 8601.
sessionA random id for this viewing: one page load, one player.
videoThe manifest's id.
position, durationSeconds, in the visible timeline (after any trim).
dataThe event's own payload, as plain JSON.
contextWhatever you passed in context, on every event.

Which events

By default, the ones that say how a lecture was watched, never the per-second time or the internal sync events. events: 'all' sends everything; a list sends just those.

Typedata
play, pause, ended, seek:end{ at }
ratechange{ rate }
error{ error: { code, message, retryable } }
stall:end{ stream, durationMs }: how long it buffered
quality:change{ qualities, selected, playing }
audio:tracks{ tracks, active }
chain:phase{ from, to, skipped }: intro, content, outro
live:status{ stream, status, retryInMs }
engine:attach:ok{ engine, resumeAt }: playback could start
manifest:resolve:fail{ error }
milestone{ percent }: 25, 50 and 75 played through, a seek past them does not count; 100 at the end
session:end{ watched, milestones }: seconds really watched, each second once

Options

OptionDefaultWhat it does
endpointnoneWhere batches are POSTed.
sendnoneYour function, given each batch. Wins over endpoint.
eventsthe list aboveWhich bus events to send, or 'all'. Milestones and the session summary always go.
sample1Share of sessions reported, 0 to 1, decided once per session.
contextnoneAdded to every event.
flushEvery10Seconds between batches.

Recipes

Google Analytics 4

analytics: {
  send: (events) => events.forEach((e) =>
    gtag('event', e.type.replace(':', '_'), { video_id: e.video, position: e.position, ...e.data })),
}

Matomo

analytics: {
  send: (events) => events.forEach((e) =>
    _paq.push(['trackEvent', 'Video', e.type, e.video, Math.round(e.position)])),
}

Your own endpoint (Node)

app.post('/collect', express.text({ type: '*/*' }), (req, res) => {
  const events = JSON.parse(req.body);   // fetch sends JSON, the last beacon text/plain
  saveEvents(events);
  res.sendStatus(204);
});

Privacy

No personal data: a random session id, the video's id, the position and what the player did. Nothing identifies the viewer unless you put it in context, deliberately. With sample, only a share of sessions is reported at all.

xAPI

For a learning platform, @nanoplayer/plugin-xapi reports what was watched and whether the lecture was completed, as xAPI Video Profile statements that any LRS understands. 

import '@nanoplayer/plugin-xapi';

create('#player', {
  manifest,
  plugins: {
    xapi: {
      endpoint: 'https://lrs.example.org/xapi',
      auth: 'Basic ' + btoa('key:secret'),
      actor: { objectType: 'Agent', mbox: 'mailto:student@example.org' },
      // or: send: (statement) => lms.record(statement),
    },
  },
});
  • One statement per request, POSTed to <endpoint>/statements with X-Experience-API-Version: 1.0.3, your Authorization header and keepalive, so the last one survives closing the tab.
  • With send, your function gets each statement instead: the usual way when the LMS records through its own channel (cmi5, a backend that adds the actor).
  • The actor comes from you: the player does not know who is watching.
VerbWhenResult extensions
initializedThe first play, not page load: unwatched videos send nothing.
playedEach play.time
pausedEach pause.time, progress, played-segments
seekedEach seek.time-from, time-to
completedOnce, when the share really watched reaches completionThreshold (0.9). Dragging to the end does not complete it.progress, played-segments, plus completion: true and duration
terminatedWhen the page goes away.time, progress, played-segments

Every statement carries the profile in context.contextActivities, and session-id, length and completion-threshold as context extensions. The activity id is activityId, or urn:nanoplayer:video:<manifest id>. The intro and outro are not the lecture: they neither count nor report.

OptionWhat it does
endpoint, authThe LRS and its Authorization header.
sendYour function, given each statement. Wins over endpoint.
actorWho is watching, as xAPI expects it.
activityIdThe activity's IRI.
registrationThe xAPI registration, when the LMS uses one.
completionThresholdShare watched, 0 to 1, that completes it. 0.9 by default.

The manifest's fields are in the manifest reference. Source on GitHub.
