Manifest reference

The manifest describes one lecture: its videos, intro and outro, captions, chapters, activities and thumbnails. Pass it to the player as an object, or as the URL of a JSON file.

Manifest

FieldTypeWhat it does
id requiredstringIdentifies the lecture: where the position is remembered, what analytics and xAPI report.
titlestringShown on the lock screen and in playlists; named in xAPI statements.
posterURLThe image before playback. The player can also take it directly, to show it without fetching the manifest.
durationsecondsKnown in advance, the bar shows the length before a byte is downloaded.
streams requiredStream[]One video, or two kept in sync: the speaker and the slides.
intro, outroBumperChained before and after the content. The intro can be skipped; the outro cannot.
annotationsAnnotation[]Data anchored to the timeline: a trim, chapters, activities.
textTracksTextTrack[]Captions, subtitles and descriptions, as WebVTT.
thumbnailsURLA WebVTT file of pictures for the progress bar: Thumbnails.
livebooleanA live broadcast: Live.
liveWaitingImageURLLive only: the image while the broadcast has not started. Falls back to the poster.

Streams

FieldTypeWhat it does
id requiredstringUnique within the manifest.
role requiredpresenter · presentation · anyWhat the layouts arrange: speaker only, slides only, side by side, picture in picture.
audio requiredbooleanExactly one stream carries the sound: it is the clock the others follow, and iPhone cannot play two at once.
sources requiredSource[]The same video in one or more formats or qualities.
labelstringA readable name for the stream.
kindvideo · audioInferred from the MIME type; only needed when that is ambiguous, as in audio-only HLS.
posterURLThis stream's own image.

Sources

FieldTypeWhat it does
src requiredURLThe file or playlist.
type requiredMIME typePicks the engine: video/mp4 plays natively, application/vnd.apple.mpegurl through hls.js or natively on Safari.
heightpixelsWith two or more MP4 sources that declare it, each is a choice in Settings → Quality, switched keeping the position.

Intro and outro

Each is an object with sources, like a stream's: one video with its own sound. Both are optional. The intro has a Skip intro button and is not replayed by loop; the outro cannot be skipped. Not allowed on a live stream.

Annotations

All share kind, start and an optional end, in seconds of the media file. A kind no plugin knows still passes validation.

trim

Plays only start to end without editing the file: the bar, the time and seeking all count from start. One at most, it needs end, and not on a live stream.

chapter

title is required: it is read by screen readers. Marked on the bar, shown next to the time, listed in Settings → Chapters, and next and previous on the lock screen jump between them. Without end, a chapter runs to the next one.

h5p

data.src is the activity's embed URL, the one Moodle, H5P.com or WordPress give; data.title names it. Playing through start pauses the video and opens the activity over it. Only http(s) URLs are accepted.

Text tracks

FieldTypeWhat it does
src requiredURLA WebVTT file.
lang requiredBCP 47The language: without it the track cannot be offered.
kindsubtitles · captions · descriptions · chaptersSubtitles and captions are offered as captions and in the transcript. descriptions are read out to screen readers, never drawn. chapters tracks are left alone: chapters come from annotations.
labelstringThe name in the menus; else the language's own name.
defaultbooleanOn from the start. One track at most.

Thumbnails

A WebVTT file whose cues name the picture for each stretch, usually a region of one sprite sheet, so one request serves the whole bar. The image URLs are relative to the WebVTT file, not to the page. 

WEBVTT

00:00:00.000 --> 00:00:05.000
thumbs.jpg#xywh=0,0,160,90

00:00:05.000 --> 00:00:10.000
thumbs.jpg#xywh=160,0,160,90

Live

live: true turns the bar into the DVR window, adds the live badge, and waits and retries while the broadcast has not started. An intro, an outro and a trim are not allowed: the broadcast moves on while they play.

Rules

  • Relative URLs resolve against the page that shows the player, as an <img>'s would; here, against this page. Thumbnail images are the exception: relative to their WebVTT.
  • Exactly one stream with audio: true. Two are rejected rather than failing only on iPhone.
  • Validation reports every error at once, each with the path to the field and why, and unknown fields are ignored: a manifest can carry data for your own code.
  • Plugin settings are not in the manifest: they go to create(). See Analytics and xAPI for the ones that send data.
